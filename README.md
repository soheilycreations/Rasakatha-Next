# Rasakatha.lk storefront

Next.js 16 (App Router) + Tailwind v4 + Supabase, deployed on Vercel.

```bash
npm install
cp .env.example .env.local   # fill in the values
npm run dev
```

## Domain setup (rasakatha.lk)

1. In Vercel → Project → Settings → Environment Variables (Production) set
   `NEXT_PUBLIC_SITE_URL=https://rasakatha.lk`, then redeploy.
2. Vercel → Settings → Domains: add **`rasakatha.lk`** (primary) and **`www.rasakatha.lk`**.
   Set `www.rasakatha.lk` to *redirect to* `rasakatha.lk` (308), so the apex is the canonical host.
3. DNS: `A rasakatha.lk → 76.76.21.21`, `CNAME www → cname.vercel-dns.com` (or use the values Vercel shows).
   Lower the TTL a day before switching so a rollback is quick.
4. While the site is on `*.vercel.app`, every response carries `X-Robots-Tag: noindex`
   (see `next.config.ts`); it stops applying automatically once traffic arrives on rasakatha.lk.

### Old WooCommerce URLs

Old product/category/shortlink URLs 308-redirect to the new pages:

| Old | New |
| --- | --- |
| `/books/<slug>`, `/product/<slug>` | `/book/<id>-<slug>` |
| `/product-category/<slug>` | `/category/<slug>` (or `/categories` when it has no clean match) |
| `/?p=<id>`, `/?post_type=product&p=<id>` | `/book/<id>-<slug>` |
| `/shop`, `/my-account`, `/about-us`, `/contact-us`, … | see `redirects()` in `next.config.ts` |

Slug data lives in `src/lib/data/legacy-*.json`, generated by
`scripts/extract-legacy-urls.mjs` (from the WooCommerce SQL dump) and
`scripts/build-legacy-maps.mjs`. Handlers: `src/app/legacy/**`.

## Environment variables

See `.env.example`. Analytics and Search Console are optional and only load when set:
`NEXT_PUBLIC_GA_ID`, `NEXT_PUBLIC_META_PIXEL_ID`, `NEXT_PUBLIC_GSC_VERIFICATION`.

## Admin: staff accounts and security

Staff sign in at /admin/login with email + password (Supabase Auth). Roles: owner, manager, cashier, stock keeper
(permission matrix: `src/lib/permissions.ts`). Owners and managers must use a 2FA authenticator app; cashiers can
use a 4-6 digit PIN to switch users at the till. Every change is recorded in /admin/audit.

Set up (once): run `supabase/admin-phase-0.sql`, then
`node --env-file=.env.local scripts/create-owner.mjs you@example.com "Your Name" "a-long-password"`.

### Environment variables

| Variable | Scope | What | How to make it |
| --- | --- | --- | --- |
| `ADMIN_SESSION_SECRET` | Preview + Production (may differ) | signs sessions | `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"` |
| `ADMIN_ENCRYPTION_KEY` | Preview + Production (**must be identical**: they share one database) | encrypts 2FA secrets | same command; 32+ characters; never change it once staff have enrolled 2FA |
| `ADMIN_PASSWORD` | Production | emergency owner password | a long passphrase |
| `ADMIN_EMERGENCY_LOGIN` | Production | `true` enables the emergency password login | leave unset normally; it also works automatically until the first owner exists |

### Lost phone (2FA recovery)

1. Use one of the 10 one-time **recovery codes** shown at 2FA setup ("Lost your phone?" on the sign-in step).
2. Another owner opens /admin/staff, picks the person and chooses **Reset two-factor (lost phone)** (audited).
3. If the only owner is locked out: set `ADMIN_EMERGENCY_LOGIN=true`, sign in with `ADMIN_PASSWORD`, reset your own two-factor in /admin/staff, then unset the flag.
4. Last resort: `node --env-file=.env.local scripts/reset-2fa.mjs someone@example.com` (needs server access; audited).
